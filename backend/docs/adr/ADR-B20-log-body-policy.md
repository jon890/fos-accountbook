# ADR-B20: 운영 로그에 요청과 응답 본문을 남기지 않는다 (2026-10-01)

- **status**: `accepted`
- **결정**: 요청 응답 로깅은 INFO 에 메서드, 경로, 상태, 처리 시간만 남긴다. 본문은 DEBUG 에서만 남기고, 인증 경로(`/api/v1/auth/**`)와 연동 토큰 발급 경로의 본문은 DEBUG 에서도 남기지 않는다.
  비즈니스 예외는 4xx 를 WARN 으로 스택 없이, 5xx 를 ERROR 로 스택과 함께 남긴다. 오류 응답의 `parameters` 는 `debugInfo` 와 같이 local, dev, test 프로파일에서만 싣는다.
  경로에 담긴 초대 토큰은 `***` 로 가리고, 쿼리는 키만 남겨 모든 값을 `***` 로 가린다. DEBUG 에도 같은 규칙을 적용한다.
- **맥락**: 운영 프로파일이 `com.bifos.accountbook` 을 INFO 로 두고, 응답 로깅 필터가 모든 응답 본문을 1000자까지 INFO 로 남겼다.
  소셜 로그인과 refresh 응답의 access token, refresh token 원문, 그리고 가계부 금액이 운영 로그에 쌓였다(2026-10-01 점검).
  가리는 예외는 연동 토큰 발급 경로 하나뿐이라, 새 민감 경로가 생길 때마다 빠뜨릴 수 있었다.
  4xx 비즈니스 예외도 ERROR 와 스택으로 남아 실제 장애가 묻혔고, 응답의 `parameters` 에 초대 토큰 같은 값이 실렸다.
- **대안 기각**:
  - 민감 경로만 골라 가리기: 경로가 늘 때마다 목록을 고쳐야 하고, 빠뜨리면 다시 샌다. 금액 같은 개인 데이터는 계속 남는다.
  - 본문에서 토큰 필드만 정규식으로 지우기: 필드 이름이 바뀌거나 중첩되면 놓친다.
- **결과**:
  - 얻는 것: 운영 로그에 토큰과 가계부 내용이 남지 않는다. 장애 로그가 4xx 에 묻히지 않는다.
  - 감당할 것: 운영에서 요청 내용을 보려면 일시적으로 DEBUG 를 켜야 한다. 그때도 인증 경로 본문은 보이지 않는다. 프론트엔드가 운영 오류 응답의 `parameters` 를 읽지 않아야 한다.
- **적용 범위**: `RequestResponseLoggingFilter`, `GlobalExceptionHandler`, `logback-spring.xml` 의 prod 프로파일.
