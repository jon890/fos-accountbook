# ADR-B26: 월 예산은 전체 예산이고 생활비 한도는 항목 한도를 뺀 나머지다 (2026-10-03)

- **status**: `accepted`
- **결정**: `families.monthly_budget` 은 가족의 전체 예산이다. 예산 합계는 고정지출을 뺀 모든 지출이고, 예산 항목의 지출도 포함한다.
  생활비는 따로 저장하지 않는다. 쓴 금액은 예산 합계에서 항목 카테고리의 지출을 뺀 것이고, 한도는 월 예산에서 ACTIVE 항목 한도의 합을 뺀 것이다. 뺀 값이 0 보다 작으면 0 이다.
  월 통계의 `monthlyExpense` 와 예산 알림은 예산 합계를 쓴다.
  [ADR-B25](ADR-B25-budget-items.md) 의 「생활비 한도는 `monthly_budget`」 과 「`monthlyExpense` 와 예산 알림은 생활비 합계」 를 대체한다.
- **맥락**: ADR-B25 로 배포한 뒤 사용자가 월 예산을 전체 예산으로 생각하고 넣은 값이 홈에서 「생활비」 한도로 보였다(2026-10-03).
  부부는 전체 예산 180만원에서 각자 용돈 40만원을 떼고 나머지 100만원을 생활비로 쓴다.
  설정의 「월 예산」 이라는 이름도 전체 예산으로 읽힌다.
- **대안 기각**:
  - 맨 윗줄 이름만 「예산」 으로 바꾸기: 그 줄에 용돈이 빠져 있어 이름과 뜻이 어긋난다.
  - 생활비도 카테고리를 고르는 항목으로 등록하기: 새 카테고리를 만들 때마다 넣어야 하고 빠뜨리면 어느 항목에도 세지 않는다(ADR-B25 의 기각 이유와 같다).
  - 항목 한도 합이 월 예산을 넘으면 저장을 거부하기: 월 예산을 줄일 때도 검사해야 하고, 두 사람이 순서를 맞춰 고쳐야 한다. 넘으면 홈에 표시만 한다.
- **결과**:
  - 얻는 것: 전체 예산 180만원, 각자 용돈 40만원, 생활비 100만원을 월 예산과 용돈 항목 둘만으로 표현한다. 예산 화면, 예산 알림, 홈 맨 윗줄이 같은 숫자를 쓴다.
  - 감당할 것: 배포 뒤 `monthlyExpense` 와 예산 알림 기준 금액이 다시 늘어난다. 항목 카테고리의 지출이 들어오기 때문이다. 기존에 생활비 한도로 넣은 월 예산은 사용자가 전체 예산으로 고쳐야 한다.
    생활비 규칙과 예산 합계 규칙이 서로 달라 쿼리가 둘이 된다. 예산 합계 규칙은 QueryDSL 쿼리와 JPQL 쿼리 두 곳에 있어 함께 고친다.
- **적용 범위**: `dashboard` 도메인, `ExpenseJpaRepository` 의 예산 알림 합계 쿼리, 프론트엔드 달력 홈과 예산 화면.
