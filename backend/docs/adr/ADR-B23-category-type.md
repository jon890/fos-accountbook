# ADR-B23: 카테고리를 지출용과 수입용으로 나눈다 (2026-10-01)

- **status**: `accepted`
- **결정**: 카테고리에 종류(`type`: `EXPENSE`, `INCOME`)를 둔다. 지출과 반복 지출은 `EXPENSE` 카테고리만, 수입은 `INCOME` 카테고리만 쓸 수 있고 맞지 않으면 400 이다.
  기본 카테고리는 종류마다 하나다(지출 「미분류」, 수입 「기타 수입」). 카테고리를 지우면 그 카테고리의 지출과 반복 지출은 지출 기본으로, 수입은 수입 기본으로 옮긴다.
  새 가족은 지출 기본 카테고리와 함께 수입 카테고리 「급여」, 「부수입」, 「용돈」, 「기타 수입」 을 받는다.
- **맥락**: 카테고리에 종류가 없어 수입을 등록할 때도 식비, 카페 같은 지출 카테고리가 같이 나왔다(2026-10-01 등록 화면 평가). 카테고리를 지울 때 수입은 옮기지 않아 지워진 카테고리를 계속 가리켰다.
- **대안 기각**:
  - 프론트에서 이름으로 수입 카테고리를 추정하기: 사용자가 만든 카테고리는 분류할 수 없고 백엔드 검증이 없다.
  - 종류 없이 카테고리마다 「수입에도 표시」 플래그: 한 카테고리를 두 곳에 쓰면 통계와 예산 제외의 의미가 섞인다.
- **결과**:
  - 얻는 것: 등록 화면이 종류에 맞는 카테고리만 보여 준다. 카테고리 삭제 뒤 수입이 지워진 카테고리를 가리키지 않는다.
  - 감당할 것: 배포할 때 마이그레이션이 기존 카테고리를 쓰임새로 분류한다. 수입에만 쓰인 카테고리는 `INCOME`, 그 밖은 `EXPENSE` 다. 지출과 수입 양쪽에 쓰인 카테고리는 `EXPENSE` 로 두고, 그 카테고리를 쓰던 수입은 그 가족의 「기타 수입」 으로 옮긴다. 외부 연동(fos-agents 가계부 플러그인)은 수입을 등록할 때 `INCOME` 카테고리를 골라야 한다.
- **적용 범위**: `category`, `expense`, `income`, `recurring` 도메인, 새 Flyway 마이그레이션.
