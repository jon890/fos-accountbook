# ADR-F35: 화면 바깥 여백은 레이아웃이 갖고 카드 여백은 카드 부품이 갖는다 (2026-10-01)

- **status**: `accepted`
- **결정**: 로그인 뒤 화면의 바깥 여백은 인증 레이아웃의 `main`(`px-3 sm:px-6 lg:px-8`, `pt-3 md:pt-6`) 하나만 준다. 화면 컴포넌트와 `loading.tsx` 는 바깥 좌우, 위 여백을 다시 주지 않는다.
  `Card` 는 여백을 갖지 않고(`py-0 gap-0`), 여백은 `CardHeader`, `CardContent`, `CardFooter` 가 모바일 값부터 반응형으로 갖는다. 카드와 섹션 안쪽은 `p-4 md:p-6`, 리스트 항목은 `p-3 md:p-4`, 섹션 간격은 `space-y-4 md:space-y-6` 을 기준으로 한다.
  다이얼로그는 모바일에서 `p-4`, `sm` 이상에서 `p-6` 이다.
- **맥락**: 390px 폭에서 카테고리, 알림, 예산, 가족, 초대 화면의 여백이 크다는 사용자 지적이 있었다(2026-10-01).
  조사해 보니 shadcn `Card` 기본값 `py-6 gap-6` 을 덮어쓰는 곳이 하나도 없어 `CardContent` 를 줄여도 위아래 24px 가 남았다. 몇몇 화면은 레이아웃이 준 여백 위에 `px-4`, `py-6` 을 다시 쌓아 좌우 28px 가 됐다. 반응형 여백 규칙이 문서에 없어 화면마다 따로 정했다.
- **대안 기각**:
  - `Card` 기본값만 `py-4 md:py-6` 으로 줄이기: 데스크톱은 그대로지만, `CardContent` 에 여백을 준 13개 사용처 대부분에서 모바일도 16px 와 16px 가 겹친다.
  - 화면마다 덮어쓰기: 새 화면이 생길 때마다 같은 실수가 다시 난다.
- **결과**:
  - 얻는 것: 모바일에서 콘텐츠가 화면 끝에서 12px 안쪽에 일정하게 놓인다. 새 카드는 부품만 쓰면 여백이 맞는다.
  - 감당할 것: `Card` 에 부품 없이 내용을 바로 넣으면 여백이 0 이다. 그런 카드는 안쪽 요소가 `p-4 md:p-6` 을 갖는다. 여백 회귀는 `browser/` 의 폭별 단언으로 잡는다(ADR-F34).
- **적용 범위**: `src/components/ui/card.tsx`, `dialog.tsx`, `alert-dialog.tsx`, `src/components/empty/EmptyState.tsx`, `src/app/(authenticated)/` 아래 화면과 `loading.tsx`.
