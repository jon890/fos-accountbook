# ADR-F34: 브라우저 테스트는 가짜 백엔드와 직접 만든 세션으로 돌린다 (2026-10-01)

- **status**: `accepted`
- **결정**: 해상도별 화면 검증은 Playwright 로 한다. 빌드한 Next 서버를 띄우고 `BACKEND_API_URL` 을 테스트가 띄운 가짜 HTTP 서버로 돌린다.
  로그인은 `AUTH_SECRET` 으로 NextAuth 세션 쿠키를 직접 만들어 넣는다. 같은 테스트를 모바일(390×844)과 데스크톱(1280×900) 두 project 로 돌린다.
- **맥락**: 모바일 여백처럼 특정 폭에서 어떻게 보이는지는 jsdom 이 레이아웃을 계산하지 않아 Jest 로 확인할 수 없다.
  Server Action 은 Next 서버에서 백엔드를 부르므로, 브라우저 요청을 가로채는 `page.route` 로는 백엔드 응답을 바꿀 수 없다.
  로그인 뒤 화면은 OAuth 를 거쳐야 열린다.
- **대안 기각**:
  - 실제 백엔드와 MySQL 을 Docker Compose 로 함께 띄우기: 이전 계획이었다. CI 마다 백엔드 이미지와 DB 를 띄우고 데이터를 심어야 해서 느리고, 화면 하나의 상태(알림 0건, 카테고리 30개)를 만들기 어렵다.
  - `page.route` 로 응답 바꾸기: 서버에서 나가는 요청에 닿지 않는다.
  - 화면 스크린샷 비교: 글꼴과 운영체제에 따라 픽셀이 달라 CI 와 로컬 결과가 어긋난다. 위치와 계산된 스타일을 숫자로 단언한다.
- **결과**:
  - 얻는 것: 로그인 뒤 화면을 폭별로 열어 `boundingBox()` 와 `getComputedStyle()` 로 여백을 숫자로 확인한다. 백엔드 없이 PR 마다 돈다.
  - 감당할 것: 가짜 백엔드 응답은 백엔드 계약을 손으로 따라 쓴 것이라 계약이 바뀌면 함께 고쳐야 한다. 가짜 백엔드가 모르는 경로를 받으면 테스트를 실패시켜, 화면이 새 API 를 부르기 시작한 것을 놓치지 않는다.
- **적용 범위**: `frontend/browser/`, `.github/workflows/frontend-ci.yml` 의 browser job.
