# ADR-F38: 다크 모드 색은 토큰이 맡고, 테마는 기기마다 고른다 (2026-10-01)

- **status**: `accepted`
- **결정**: 화면 코드는 Tailwind 기본 팔레트(`gray-*`, `blue-*`, `white`, `black` 등)를 쓰지 않고 `globals.css` 의 토큰만 쓴다.
  라이트 전용 값을 가진 토큰은 `[data-theme="dark"]` 에서 모두 다시 정의한다.
  옅은 바탕(`brand-tint`, `brand-50` 부터 `brand-200`), 그 위 글자(`brand-700` 부터 `brand-900`), 카테고리 바탕과 글자, 바탕 그라디언트가 여기 해당한다.
  `brand-300` 부터 `brand-600` 은 버튼과 강조색이라 두 테마에서 같은 값을 쓴다.
  테마와 무관하게 흰 바탕 위에 놓이는 요소는 다크에서 바뀌지 않는 토큰(`neutral-0`, `brand-ink`)을 쓴다.
  팔레트 사용은 단위 테스트가 소스를 검사해 막고, 외부 브랜드 색처럼 정해진 예외만 테스트의 허용 목록에 둔다.
  사용자는 설정 화면에서 시스템, 라이트, 다크 중 하나를 고르고, 그 값은 그 기기의 브라우저에만 저장한다.
- **맥락**: 다크 모드에서 카테고리 창, 내역 카테고리별 지출 카드, 설정의 선택 행, 알림 안읽음 바탕이 흰 판이나 옅은 판으로 떴다(이슈 #357, 2026-10-01 조사).
  원인은 둘이었다. 다크 블록이 표면 토큰만 다시 정의하고 `brand-50`, `cat-*-bg`, 그라디언트 같은 라이트 전용 값은 그대로 뒀다. 그리고 14개 파일이 `gray-*`, `bg-white` 를 직접 썼다.
  테마는 기기 설정만 따라가 사용자가 다크를 끌 방법이 없었다.
- **대안 기각**:
  - 화면마다 `dark:` 변형을 붙이기: 같은 색 짝을 사용처마다 두 번 쓰게 되고, 새 화면에서 빠뜨리면 같은 문제가 다시 난다.
  - brand 스케일 전체를 다크에서 뒤집기: `hover:bg-brand-600` 처럼 진한 단계를 버튼에 쓰는 곳이 밝아져 흰 글자 대비가 떨어진다.
  - 테마 선택을 계정에 저장하기: 백엔드 변경이 필요하고, 휴대폰과 PC 에서 다른 테마를 원하는 경우를 막는다.
- **결과**:
  - 얻는 것: 토큰을 고치면 그 토큰을 쓰는 화면이 함께 바뀐다. 팔레트를 다시 쓰면 `pnpm test` 가 실패한다.
  - 감당할 것: 새 색이 필요하면 화면에서 바로 쓰지 못하고 토큰을 먼저 만들고 다크 값까지 정해야 한다. 테마 선택은 기기를 바꾸면 다시 골라야 한다.
- **적용 범위**: `src/app/globals.css`, `src/app/providers.tsx`, `src/components/ui/sonner.tsx`, 설정 화면, `src/` 아래 모든 화면 코드.
