# ADR-F40: 모바일 금액 입력은 시트 안 숫자패드로 하고, 저장할 수 없는 이유를 버튼 위에 보인다 (2026-10-02)

- **status**: `accepted`
- **결정**: 768px 미만에서 거래 등록과 수정 시트의 금액은 시트 안에 그린 숫자패드(1~9, 00, 0, 지우기)로 입력한다. 이 폭에서는 기기 키보드를 띄우지 않는다. 768px 이상에서는 지금처럼 키보드로 입력한다.
  저장 버튼은 필수 값이 비면 비활성이고, 그 위에 첫 번째로 빠진 값을 한 줄로 알린다. 저장 중에는 폼 전체를 `fieldset disabled` 로 잠근다.
  모바일의 카테고리 추가와 수정 창은 하단 시트로 띄운다(BudgetEditDialog 와 같은 반응형 규칙).
- **맥락**: 등록 화면 평가에서 금액을 누르면 기기 키보드가 올라와 시트의 절반을 가리고, 카테고리와 저장 버튼이 키보드 뒤로 밀렸다(2026-10-01). 사용자는 시트 안 숫자패드를 골랐다.
  금액을 비운 채 저장을 누르면 서버 검증 오류가 토스트로만 떠 무엇을 고쳐야 하는지 보이지 않았다. 저장 중에도 입력이 바뀌어, 보낸 값과 화면 값이 달라질 수 있었다.
  카테고리 창은 모바일에서도 가운데 다이얼로그로 떠, 등록 시트와 다른 모양이었다.
- **대안 기각**:
  - 기기 키보드 유지(`inputMode="numeric"`): 시트 높이를 키보드가 차지하고, 기기마다 모양과 높이가 달라 배치를 맞출 수 없다.
  - 저장 버튼을 늘 켜 두고 제출 뒤 오류 표시: 무엇이 빠졌는지 누른 뒤에야 알 수 있고, 금액 0 같은 흔한 실수가 왕복 요청을 만든다.
- **결과**:
  - 얻는 것: 금액, 카테고리, 저장 버튼이 한 화면에 함께 보인다. 빠진 값이 버튼 위에 바로 보인다.
  - 감당할 것: 붙여넣기와 음성 입력은 모바일 금액 칸에서 쓸 수 없다. 숫자패드는 접근성(버튼 이름, 지우기 길게 누르기 없음)을 직접 챙겨야 한다.
- **적용 범위**: `src/components/expenses/forms/AmountInput.tsx`, 새 숫자패드 컴포넌트, `src/components/transactions/dialogs/`, `src/app/(authenticated)/categories/_components/` 의 추가, 수정 창.
